# Архитектура

## Разделение кода

Файлы `app/**/page.tsx` подключают страницы из `features`. Каждая feature содержит свой интерфейс, запросы, контракты и стили. Общие компоненты находятся в `components/ui`, навигация — в `components/layout`.

В админке `admin-page.tsx` выбирает раздел, `resource-panel.tsx` показывает записи, `resource-editor.tsx` редактирует их, `resources.ts` описывает ресурсы и чтение списков. `fields.json` генерируется из OpenAPI. Ручные изменения в нём будут перезаписаны генератором.

Пользовательские награды находятся в `features/rewards`: страница отвечает за отображение, `use-rewards.ts` — за запросы и состояние. Материалы курса и механизм импорта изолированы в `features/admin/course-import`.

## Сессия и запросы

`services/api/create-client.ts` создаёт публичный и авторизованный Axios-клиенты. Access token хранится в памяти, refresh token — в sessionStorage текущей вкладки. Токены не передаются через URL и не выводятся в логи.

Параллельные запросы используют одно обновление токена. После 401 запрос повторяется максимум один раз. Неверный refresh-ответ завершает сессию; сетевая ошибка допускает новую попытку. При смене аккаунта поколение сессии меняется: поздние ответы отменяются, Query cache и черновики чатов очищаются.

TanStack Query хранит серверные данные. Изменения инвалидируют связанные запросы. Проверка `admin` в интерфейсе ограничивает доступ к элементам управления; разрешения на операции проверяет сервер.

## Уроки

`contracts.ts` проверяет ответы API, `exercise-adapter.ts` определяет доступные типы, `use-lesson-attempt.ts` управляет попыткой. Переход вперёд возможен после серверного `correct: true`. Завершение локальной сессии и сохранённый прогресс урока отображаются отдельно.

`/exercise-preview` использует отдельные примеры и локальную проверку. Результаты предпросмотра не отправляются в API.

## Чаты

Активная переписка обновляется опросом API. Скрытый список на мобильном экране не опрашивается. Черновики хранятся в памяти с ключом пользователя и чата; подтверждение отправки очищает только отправленную версию текста. Подтверждение прочтения изменяет только `is_read`, не перезаписывая содержание сообщения.

## Оформление

SCSS Modules используют семантические переменные из `styles`. Тема поддерживает светлый, тёмный и системный режимы. Переводы находятся в `i18n`; cookie языка используется при серверном рендеринге. Общие диалоги используют native dialog и счётчик блокировки прокрутки.

## Проверки

`npm run check` проверяет типы, неиспользуемые локальные переменные и параметры, ESLint, Prettier, тесты, словари, контраст и сборку. Тесты покрывают авторизацию, контракты упражнений, прогресс, сообщения, черновики и повторный импорт. Визуальная и авторизованная проверка в браузере выполняется отдельно.
