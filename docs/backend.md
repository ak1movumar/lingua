# Интеграция с API

Снимок контракта: [openapi.json](openapi.json). Адрес API задаётся через `NEXT_PUBLIC_API_URL`. Типы в `src/types/api.generated.ts` и поля админки генерируются командой `npm run api:generate`.

Актуальный сервер: `http://54.90.250.224`, схема загружена с `/openapi.json` 21 сентября 2026 года.

## Обновление интеграции

- `/learning-path` показывает персональный уровень, статус вступительного теста и доступность курсов. Уроки используют блокировки персонального маршрута, включая прямые ссылки.
- `/level-tests/[language_id]` запускает вступительный тест; `?level=A1` запускает итоговый тест уровня. Все ответы отправляются одной попыткой, результат и уровень берутся из сервера. Поддержаны строковые вопросы `translate` и `fill_gap`; для `choice` и `match` сохраняется ограничение ниже. Вопросы с неизвестным контрактом не отправляются с выдуманным ответом.
- В `/admin` добавлены создание, изменение и удаление тестов и их вопросов. Список вопросов доступен из карточки теста. Правильные ответы доступны только в административном редакторе.
- Поиск использует `/users/search?q=...`; публичный профиль — `/users/{id}/public`. Заявки в друзья и добавление участников чата передают `username`. Имена участников, отправителей и рейтинга берутся из вложенных публичных профилей.
- В новой схеме отсутствуют `/notifications` и реакции на сообщения. Их элементы интерфейса отключены; фоновые запросы к ним больше не выполняются.
- После завершения теста или урока обновляются данные о доступе и прогрессе. Автоматические повторы POST-запросов теста отключены.

## Неуточнённые контракты

| Область                 | Что требуется уточнить                                               |
| ----------------------- | -------------------------------------------------------------------- |
| `choice`, `match`       | Структура `options`, идентификаторы вариантов и формат `answer`      |
| `translate`, `fill_gap` | Приём строкового ответа, регистр, пробелы и допустимые варианты      |
| Прогресс                | Условия завершения урока, итоговый балл и открытие следующего урока  |
| XP и streak             | Повторные попытки, начисление наград и часовой пояс                  |
| Задания дня             | Механизм выполнения и выдачи награды: отдельный endpoint не объявлен |
| `/auth/refresh`         | Точный ответ и правила обновления refresh token                      |
| Друзья                  | Допустимые статусы заявки и переходы между ними                      |
| Групповые чаты          | Семантика `is_read` и права управления участниками                   |

Для примеров упражнений используйте [шаблон](backend-exercise-examples.request.json). Это запрос документации, а не тело API-запроса.

## Текущая обработка

Реальные уроки отправляют строковые ответы для перевода и пропусков. Choice/match доступны в отдельном предпросмотре; их отправка в настоящий урок заблокирована до уточнения контракта. `correct_answer` не берётся из пользовательского ответа API и не используется для локальной проверки реального урока.

Refresh-ответ проверяется во время выполнения. Если новый refresh token отсутствует, сохраняется текущий. Неожиданный формат завершает локальную сессию.

Статусы заявок отображаются как строки сервера. Рейтинг и XP берутся из API. Для заданий дня показываются данные; самостоятельного начисления наград во фронтенде нет.

## Развёртывание и проверка

Бэкенд должен проверять права на все административные операции. Нужны тестовые аккаунты `user` и `admin` и заполненный учебный курс для проверки полного сценария. Подключённые сценарии требуют проверки с этими аккаунтами; успешная сборка не доказывает корректность серверной логики.

HTTPS-фронтенду необходим HTTPS API и разрешённый CORS origin. Большие списки сейчас загружаются целиком: серверная пагинация в используемых endpoints не описана.
